Build time — when you run docker build . This is when Docker reads your Dockerfile top to bottom and constructs the image (think of an image as a frozen, reusable template/snapshot of a filesystem — like a zip file of an entire mini Linux install with your software already in it).
Run time — when you run docker run <image> (or docker compose up). This is when Docker takes that frozen template and boots it into a live, running container — an actual process on your machine, with its own process ID, that starts executing and keeps running until it exits or you stop it.
----------------------------------------------------------------
RUN only exists to help you construct the image. When Docker hits RUN apt-get install ..., it temporarily spins up a throwaway container, runs that command inside it, takes a snapshot of the resulting filesystem (that's the new "layer"), and then throws that temporary container away. This all happens once, during docker build, before anyone has asked for a running container yet. The result of the command (the installed files) gets baked into the image, but the command itself never runs again after the build finishes.
ENTRYPOINT (and CMD) is different: it doesn't run at all during the build. It's just a instruction stored in the image's metadata that says "whenever someone starts a container from this image, run this command first." So every single time you do docker run (or restart the container, or docker-compose spins it up), that command executes fresh, from scratch, in a brand new live process.
